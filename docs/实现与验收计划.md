# 实现与验收计划

## 工程结构

仓库采用 Vite、React、Lucide 和 Playwright。每个方案有独立 React 模块，薄 HTML 入口只声明路由。

```text
boards/<board>/index.html
boards/<board>/agent.html
boards/<board>/list.html
boards/<board>/pipeline.html
boards/<board>/matching.html
boards/<board>/cards.html
boards/<board>/upload.html
boards/<board>/tasks.html
src/moodboards/*.jsx
src/experiences/*Experience.jsx
src/components/BoardHeader.jsx
src/styles/experience-*.css
src/styles/dashboard-overviews.css
public/previews/<board>.png
tests/moodboards.spec.js
```

## 独立实现门禁

1. 每套风格拥有自己的八个页面、组件目录、样式 token、状态和动效实现。
2. 同一风格内部复用该风格自己的组件；不同风格不共享可见 UI 组件、页面 DOM 或业务交互状态机。
3. 下拉菜单、日期选择、Checkbox、Radio、Toggle、上传、Tabs、Modal、Drawer、Toast 和 Tooltip 可以使用 Radix 行为基元保证键盘与焦点行为，但每套风格分别完成外观、布局和反馈。
4. 路由、Lucide 图标、无障碍工具、截图工具和测试基础设施允许共享。
5. 生成页面前删除整个 `boards/` 目录，防止已淘汰方案残留在构建产物。
6. 模式切换在每个页面都可见，按风格保存用户选择；首屏脚本在 React 渲染前设置主题，避免亮色闪烁。
7. 每套风格为 Portal 建立独立主题容器；Dropdown、Popover、Calendar、Tooltip、Modal、Drawer 和 Toast 必须从该容器获得字体与视觉 token，不能依赖业务页面根节点的后代选择器。
8. 全局只保留必要的 normalize；浏览器原生控件可以作为隐藏的语义或无障碍载体，但用户可见部分必须由风格组件实现。

## 测试门禁

1. 十套方案 × 八类页面 × 两种模式 × 三种视口，共 480 个视觉组合。
2. 每套页面逐一验证 hover、键盘焦点、筛选、上传、拖动、Modal、Toast、Tooltip、异步反馈和业务状态变化。
3. 额外验证首页数量、真实预览图、十套独立实现、深浅模式持久化、业务状态不丢失和废弃路由清除。
4. 自动测试后生成桌面、iPad、iPhone 的关键页面接触图，并分别覆盖深浅模式，进行人工截图对比。
5. 发布前执行 `npm run build`、`npm run test:e2e`、`npm run capture:previews`、`npm run capture:review` 和 `git diff --check`。
6. Playwright 打开每套风格的下拉菜单、日期面板、Tooltip、Modal、Drawer 和 Toast，校验计算字体、字号、背景、边界与按钮外观，并截图比对；检测到系统默认样式即判定失败。
7. 平板导航必须保持水平排列；手机导航必须贴合视口底部，同时保留顶部返回、方案名和主题切换。Checkbox 的勾选图标按像素检查水平与垂直居中。

## 发布门禁

1. 首页与全部 80 个业务页面可访问，最终页面不显示风格编号。
2. GitHub Pages Action 构建成功。
3. 在线页面按十套风格抽查八类页面、深浅模式、下拉、Modal、拖动、上传和任务反馈。
4. 线上首页预览与对应 Dashboard 一致。
