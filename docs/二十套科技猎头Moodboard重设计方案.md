# Hunter SaaS 二十套 Moodboard 设计与验收方案

## 1. 目标与边界

本轮不是为同一套后台替换二十种颜色，而是为 Hunter SaaS 建立二十套可独立进入产品深化的设计方向。每套方案都必须像真实产品：能承载高频猎头工作、复杂业务资产、Agent 长任务和移动端操作。

已确认的总体比例：

1. **70% 专业猎头 SaaS：** 任务判断、岗位和候选人决策、流程推进、关系维护、结果审核和业务数据管理。
2. **20% 人文与品牌质感：** 人物、关系、信任、职业经历、顾问服务和产品辨识度。
3. **10% 克制的智能感：** 通过信息结构、证据、反馈、动效和材质体现，不依赖终端、雷达、示波器、电路等纯技术隐喻。

二十套方案都遵守以下边界：

- 首页是可用的 Hunter Dashboard，不制作营销落地页。
- 每套只有“Dashboard”和“组件与交互”两个页面；动效与组件状态融合，不建立重复的动效陈列页。
- 每套都覆盖桌面、iPad 和 iPhone，移动端保留完整业务操作，不是只读摘要。
- 不制作 3D 效果。对招聘 SaaS 而言，3D 会增加注意力和性能成本，却不能改善核心判断。
- 不采用大面积单一蓝紫色、深色控制台、渐变光球、嵌套卡片和超大营销标题。
- 二十套可以复用无障碍逻辑、业务数据与底层 React 行为，但可见布局、组件材质、状态层级和动效反馈必须服从各自设计语言。

## 2. 完整组件覆盖

每套“组件与交互”页面必须包含以下全部类别，不能因风格不同而缺少组件：

1. **应用框架：** 产品标识、主导航、二级导航、账号与工作空间、搜索、消息、移动端导航。
2. **命令与操作：** 主要、次要、弱化、危险、禁用、加载按钮；图标按钮、分裂按钮、批量操作。
3. **表单：** 普通输入、搜索、错误校验、单选下拉、可搜索多选、可创建多选、日期范围、文本域、标签编辑、文件上传、复选、单选、开关、滑杆。
4. **数据：** 指标、Tabs、筛选条、排序、批量选择、表格、分页、状态标签、进度和趋势。
5. **Hunter 业务资产：** 候选人、岗位、公司、论文、专利、Agent、人才寻访、人岗匹配、流程推进与审核。
6. **人才地图 / 思维导图：** 无限层级、展开收起、选中、负责人或候选人绑定、拖动重排、缩放、适应画布、空节点、失效关联和结构冲突。
7. **反馈：** 成功、警告、错误、加载、空状态、权限受限、骨架屏、Modal、Drawer、Toast、Tooltip。
8. **动效：** 每套四组与实际业务状态相关的交互，必须有不同触发、轨迹、节奏和完成反馈，并支持 `prefers-reduced-motion`。

## 3. 五个风格家族

| 风格家族 | 服务的核心问题 | 四套方向 |
| --- | --- | --- |
| 专业效率型 | 如何在高密度、高频操作中保持速度和稳定性 | 静默运营台、优先队列、模块工作区、清晰台账 |
| 高端顾问型 | 如何表达专业判断、客户服务和交付可信度 | 高管简报、客户会客厅、决策档案、全球顾问台 |
| 人物关系型 | 如何保留人的经历、沟通、关系和触达上下文 | 人才纪事、关系脉络、职业拼图、沟通工作台 |
| 现代品牌型 | 如何用鲜明但可维护的系统语言建立辨识度 | 瑞士网格、色彩信号、无纸化工作室、动态列阵 |
| 智能协作型 | 如何让 Agent、证据、自动化和交接可理解、可控制 | 智能副驾、自动化流水线、证据智能、协作交接台 |

## 4. 二十套详细设计

### 4.1 静默运营台 / Quiet Operations

- **设计理念：** 高频工作不应争抢注意力。通过紧凑间距、固定列和低噪声边界，让用户持续扫描今天的任务、候选人和岗位。
- **用户感受：** 安静、准确、可靠。避免“默认后台模板”和过度留白。
- **Dashboard：** 176 px 紧凑侧栏；顶部 60 px 搜索和导入命令；首行四项指标；主体为 7:5 双列，左侧优先任务和候选人，右侧岗位推进和 Agent 事件。
- **排版与色彩：** Inter / 苹方；标题 20/28，区块 14/20，正文 12/20，辅助 10/16；雾灰背景、白色表面、墨绿主色、暖橙只用于风险与增量。
- **组件系统：** 4 px 圆角、1 px 冷灰边界、无装饰阴影；按钮高度 34 px；表格行 44 px；状态以文字和细色边表达；Modal 与 Drawer 使用同一网格；思维导图使用细线、矩形节点和静默淡入。
- **动效：** 行更新 180 ms 轻亮；详情从行内展开 220 ms；完成操作仅收紧行高；数据刷新使用透明度而非旋转器。
- **响应式：** iPad 保留侧栏图标和双列；iPhone 改顶部标题、四指标 2×2、任务和候选人顺序纵排。
- **参考：** [Linear](https://linear.app/homepage) 的操作克制、[Ashby](https://www.ashbyhq.com/product-analytics) 的招聘数据密度、[Stripe Dashboard](https://docs.stripe.com/dashboard/basics) 的稳定布局。拒绝照搬开发工具深色主题。

### 4.2 优先队列 / Priority Queue

- **设计理念：** 首页先回答“下一件最值得处理的事是什么”，而不是要求用户在模块之间寻找工作。
- **用户感受：** 有序、及时、行动明确。避免把所有事项都做成同等级卡片。
- **Dashboard：** 左侧窄优先级轨，中间 5 份任务队列，右侧固定处理上下文；任务完成后下方队列自动补位。
- **排版与色彩：** Avenir Next / 苹方；数字优先级 18 px，任务 13 px；淡蓝灰背景、海军蓝操作、珊瑚色逾期边标。
- **组件系统：** 控件 38 px；按钮、表格行和卡片都有左侧优先级边；下拉选择像队列插槽；Toast 在当前任务下方反馈；思维导图节点使用队列编号和左边标。
- **动效：** 任务置顶沿纵轴上移 260 ms；完成项缩短后收拢；逾期只脉冲两次；批量推进按选中顺序依次完成。
- **响应式：** iPad 处理面板变下方抽屉；iPhone 只显示当前任务、后续队列和固定底部操作。
- **参考：** [Intercom Inbox](https://www.intercom.com/helpdesk/inbox) 的处理队列、Linear 的 Triage 思路。拒绝复制邮件客户端视觉。

### 4.3 模块工作区 / Modular Workspace

- **设计理念：** 岗位、候选人、Agent 和寻访模块随当前工作组合，但导航和关键操作位置保持稳定。
- **用户感受：** 灵活、清楚、可掌控。避免 Bento 卡片随意堆叠。
- **Dashboard：** 固定侧栏和工具条；模块按 8/4、6/6、4/8 比例排列；任务队列、候选人、岗位、Agent 使用不同固定最小尺寸。
- **排版与色彩：** Inter；轻蓝灰画布、白色模块、钴蓝主操作、橙色风险；模块标题 12 px，数据 22 px。
- **组件系统：** 8 px 圆角、低扩散阴影、模块标题轨；下拉和筛选可以吸附到当前模块；Drawer 从模块边缘展开；思维导图节点像独立模块并带吸附反馈。
- **动效：** 模块重排使用弹性收敛；上下文面板从关联模块扩展；吸附时显示位置框；恢复布局按原始顺序回位。
- **响应式：** iPad 两列；iPhone 单列任务栈，当前模块命令固定底部。
- **参考：** [Airtable Interface Designer](https://www.airtable.com/platform/interface-designer) 的组合能力、[Notion Projects](https://www.notion.com/product/projects) 的多视图。拒绝无层级的 Bento 展示。

### 4.4 清晰台账 / Clear Ledger

- **设计理念：** 招聘资产可以密集，但必须像优秀台账一样对齐、可核验、可批量处理。
- **用户感受：** 稳定、严谨、可审计。避免过多浮层和圆角卡片。
- **Dashboard：** 顶部横向指标，主体使用连续纵向账本；分组依次为待处理、候选人、岗位、Agent；列宽固定，数字右对齐。
- **排版与色彩：** IBM Plex Sans / 苹方；酒红主色、灰白画布、青绿确认色；行高 42 px，表头 11 px，数据 12 px。
- **组件系统：** 2 px 圆角或直角；横线分组、无左右边框；按钮像账本批注；表单沿统一基线；思维导图节点改为账目条并用缩进表达层级。
- **动效：** 分组折叠沿纵轴压缩；差异在左侧形成 5 px 标记；批量选中形成连续底色；写入完成后标记由风险色转确认色。
- **响应式：** iPad 冻结首列；iPhone 将每行转为字段对齐的紧凑记录，而不是普通卡片。
- **参考：** Stripe Dashboard 和 Ashby Analytics 的数据结构。拒绝财务软件的陈旧灰色表单。

### 4.5 高管简报 / Executive Briefing

- **设计理念：** 资深猎头首先做有依据的判断，Dashboard 应像一份每天更新的专业简报。
- **用户感受：** 专业、克制、有决策价值。避免杂志化大图和营销标题。
- **Dashboard：** 顶部日期和三条关键决定占 35%；下方客户组合、日程与重点候选人形成 4/3/5 三栏。
- **排版与色彩：** Georgia / 思源宋体用于标题，Source Sans 3 / 苹方用于数据；墨绿、暖白、铜金注释；正文行长不超过 66 个中文字符。
- **组件系统：** 标题与摘要使用编辑式层级；主要按钮为深墨色；次要按钮采用文字下划线；表格低边界；Modal 像决策摘要；思维导图节点像简报条目并保留章节编号。
- **动效：** 简报区块由上至下揭示；批注从右侧定位；重点切换用边界移动；摘要更新保留旧值短暂对照。
- **响应式：** iPad 简报全宽，客户和日程双列；iPhone 先三条决定，再客户、候选人和日程。
- **参考：** Ashby 的 executive dashboard、[Granola](https://www.granola.ai/use-cases/product) 的会前摘要。拒绝咨询公司官网式大面积空白。

### 4.6 客户会客厅 / Client Room

- **设计理念：** 围绕客户、委托和承诺组织空间，让用户感到 Hunter 在承载一项专业服务，而不是处理一组记录。
- **用户感受：** 体面、沉稳、被照顾。避免奢侈品式金色堆砌。
- **Dashboard：** 深色客户主信息带；下方重点客户、岗位推进和日程三栏；当前客户始终有明确入口。
- **排版与色彩：** Noto Serif SC 标题、Avenir Next 正文；深墨绿主表面、柔白内容、莓红提醒；间距比效率型增加约 20%。
- **组件系统：** 8 px 圆角但不嵌套；输入使用底线；主按钮一侧方、一侧圆形成定向感；客户卡突出承诺事项；思维导图在深色画布上使用浅色节点和聚焦光环。
- **动效：** 客户切换交叉淡化；待办提亮一次；预约确认形成日历吸附；档案收起回到客户标题带。
- **响应式：** iPad 客户头部不缩；iPhone 使用客户横向切换条，服务动作固定底部。
- **参考：** [Affinity](https://www.affinity.co/product/) 的关系型客户视图、[Pitch](https://pitch.com/) 的精致内容层级。拒绝银行 App 风格。

### 4.7 决策档案 / Decision Dossier

- **设计理念：** 每个推荐都应是一份经得起追问的档案，结论、证据和差异必须可定位。
- **用户感受：** 严谨、可信、有依据。避免把证据隐藏在 Tooltip。
- **Dashboard：** 顶部档案编号和候选人；左侧候选人摘要，右侧证据；下方职业时间线贯穿全宽。
- **排版与色彩：** Georgia 标题、Source Sans 3 正文；纸白、炭黑、砖红校样、青绿证据；双线和虚线用于档案分隔。
- **组件系统：** 1 px 圆角；按钮带审批标记；标签使用虚线；表单显示来源脊线；Modal 是前后差异稿；思维导图节点像带索引号的档案卡。
- **动效：** 档案沿左侧装订边展开；证据锚点定位；差异逐行显现；确认后出现短暂“已归档”章，不做拟物盖章声效。
- **响应式：** iPad 证据侧栏固定；iPhone 摘要与证据交替排列并保留双向锚点。
- **参考：** [Dovetail](https://dovetail.com/solutions/research-repository/) 的证据组织、Notion Docs 的文档阅读。拒绝法律软件的沉重装饰。

### 4.8 全球顾问台 / Global Advisory

- **设计理念：** 国际化的重点是区域、时区、语言和交付状态可比较，不是铺满世界地图。
- **用户感受：** 国际、精确、从容。避免国旗和地图装饰。
- **Dashboard：** 顶部跨时区带；主体采用重点客户、日程、岗位和候选人 2×2；地区索引固定在字段标题。
- **排版与色彩：** Helvetica Neue / 苹方；海军蓝、冷白、珊瑚提醒；中英文数字使用等宽数字。
- **组件系统：** 胶囊按钮只用于地区和时区；导航采用两列索引；表格地区列固定；日期选择显示时区；思维导图节点为椭圆地区单元并使用横向移动。
- **动效：** 时区切换沿横轴平移；地区筛选联动淡化；日程跨区拖动保留原时区提示；同步状态使用单次光圈。
- **响应式：** iPad 时区带可横滑；iPhone 将地区作为顶部筛选，所有时间同时显示本地时间。
- **参考：** [Deel](https://www.deel.com/solutions/payroll/) 的全球信息表达、Affinity 的客户组织。拒绝旅行应用视觉。

### 4.9 人才纪事 / Talent Journal

- **设计理念：** 候选人不是字段集合，界面需要保留职业经历、沟通与下一步行动的时间上下文。
- **用户感受：** 有温度、连续、可信。避免社交媒体动态流。
- **Dashboard：** 左侧重点人物占 25%；中间职业与沟通时间线占 50%；右侧日程和关系占 25%。
- **排版与色彩：** Noto Serif SC 人物标题、Avenir Next 数据；青灰、暖白、莓红联系事件；人物名称 24 px。
- **组件系统：** 圆形人物头像与直线时间轴组合；按钮较小；候选人卡顶部色边；Drawer 是人物侧写；思维导图节点用时间轴式竖线和人物关联头像。
- **动效：** 时间线由当前向过去展开；切换人物保持相同字段位置；新联系事件落入“现在”；回到当前时刻使用短距离滚动。
- **响应式：** iPad 人物区移顶部；iPhone 人物身份、下一步联系、时间线、关系按顺序显示。
- **参考：** Granola 的人物上下文、Notion Calendar 的时间组织。拒绝履历海报。

### 4.10 关系脉络 / Relationship Paths

- **设计理念：** 关系图只解释“如何触达”，人物、信任和下一步联系仍是主角。
- **用户感受：** 连接、可信、可行动。避免社交图谱满屏节点。
- **Dashboard：** 左侧关系路径图占 55%；右侧重点候选人占 45%；下方最佳联系路径为横向行动带。
- **排版与色彩：** Avenir Next / 苹方；深青、柔白、橙色关键路径；关系强度同时使用线宽和文字，不只依赖颜色。
- **组件系统：** 圆角节点、圆形复选和人物头像；表格悬停扩展人物关系环；Drawer 显示路径详情；思维导图使用圆形叶节点和聚合/展开。
- **动效：** 路径逐段出现；弱关系节点聚合；候选人高亮后仅相关路径保留；隐藏弱关系时节点收束而非消失闪烁。
- **响应式：** iPad 路径图全宽；iPhone 关系图改为“你 → 联系人 → 候选人”的纵向步骤。
- **参考：** [Affinity Relationship Intelligence](https://www.affinity.co/product/relationship-intelligence)。拒绝通用 network graph demo。

### 4.11 职业拼图 / Career Mosaic

- **设计理念：** 经历、能力、项目和成果是可重组片段，比较时要看共同点和缺口，而不是只有总分。
- **用户感受：** 丰富、清楚、可比较。避免 Pinterest 瀑布流。
- **Dashboard：** 左上人物与比较目标；右上能力片；中部项目片；下方候选人比较表，不同片段使用稳定尺寸。
- **排版与色彩：** Helvetica Neue / 苹方；深蓝灰、白、橙色缺口；标题和片段大小形成明显尺度差。
- **组件系统：** 5 px 圆角、轻微错位但基线稳定；选择项进入比较托盘；标签像能力片；思维导图节点允许轻微角度差并在选中时对齐。
- **动效：** 片段重排保持共享元素；加入比较从原位吸附；共同能力对齐；缺口出现使用边界而非红色闪烁。
- **响应式：** iPad 两列片段；iPhone 以比较目标为主线，片段按能力、经历、项目分组。
- **参考：** Dovetail Highlights 和 Airtable Gallery 的信息片段。拒绝作品集网站式自由排版。

### 4.12 沟通工作台 / Conversation Desk

- **设计理念：** 会话、日程和人物上下文必须共存，避免每次联系前重新查找资料。
- **用户感受：** 连续、轻松、及时。避免消费级聊天应用的娱乐感。
- **Dashboard：** 左侧会话列表 25%；中间会话 50%；右侧日程与人物上下文 25%。
- **排版与色彩：** Inter / 苹方；深青、白、莓红提醒；消息字号 12 px、行高 1.7。
- **组件系统：** 消息气泡使用非对称小圆角；输入为长胶囊但业务卡保持 8 px；会话行含下一步状态；思维导图节点使用对话气泡轮廓。
- **动效：** 接收消息从左侧进入；发送从输入区到会话；创建日程吸附到右栏；标记跟进后会话行进入对应队列。
- **响应式：** iPad 会话列表可收起；iPhone 会话、上下文、日程使用顶部三段切换，编辑不离开当前人物。
- **参考：** Intercom Inbox 和 Granola 的沟通上下文。拒绝 WhatsApp 式纯聊天视觉。

### 4.13 瑞士网格 / Swiss Recruitment Grid

- **设计理念：** 品牌感来自严格比例、强排版和清楚编号，而不是装饰。
- **用户感受：** 鲜明、理性、可信。避免海报化导致可用性下降。
- **Dashboard：** 黑色框线建立不对称 12 栏；指标 4 栏、任务 5 栏、Agent 3 栏，候选人全宽。
- **排版与色彩：** Helvetica Neue / Arial Black / 苹方；黑白占 85%，红与蓝只作功能色；标题 28 px，编号 20 px。
- **组件系统：** 直角、3 px 黑边；按钮用原色块；表头黑底；表单和 Modal 都对齐主网格；思维导图节点方正、黑框、选中后产生实体阴影。
- **动效：** 区块用遮罩揭示；编号沿工作步骤推进；布局切换按网格跳位；写入完成用下边界收束。
- **响应式：** iPad 8 栏；iPhone 4 栏但保持编号、框线和视觉顺序。
- **参考：** International Typographic Style 与 [Pitch](https://pitch.com/) 的品牌排版。拒绝简单红黑海报。

### 4.14 色彩信号 / Chromatic Signals

- **设计理念：** 颜色是稳定的业务编码：蓝为进行、绿为完成、黄为关注、红为错误，不能随页面改变含义。
- **用户感受：** 明确、醒目、快速扫描。避免彩虹仪表盘。
- **Dashboard：** 左侧 30% 大状态摘要；右侧岗位与 Agent；下方优先队列全宽，状态色沿区块边缘延续。
- **排版与色彩：** Inter / 苹方；中性灰白为主体，四种状态色总面积不超过 18%。
- **组件系统：** 4 px 圆角；按钮、标签、表格行、Toast、Modal 使用一致状态色规则；错误不能仅靠红色；思维导图的三条分支分别使用受控色带。
- **动效：** 状态变化时色边从旧状态迁移；筛选后保留相同状态位置；完成色带缩为标记；不循环闪烁。
- **响应式：** iPad 状态摘要横向；iPhone 状态带位于每条记录左侧。
- **参考：** [Asana Workflows](https://asana.com/features/workflow-automation) 与 Airtable 状态表达。拒绝装饰性色块。

### 4.15 无纸化工作室 / Paperless Studio

- **设计理念：** 简历、JD、研究资料和批注像整理良好的工作材料并置，同时具备数字连接能力。
- **用户感受：** 专注、可读、精致。避免仿真纸张和复古办公用品。
- **Dashboard：** 左侧今日工作纸 28%；中间候选人 45%；右侧证据与日程 27%。
- **排版与色彩：** Georgia / Noto Serif SC 标题、Source Sans 3 正文；暖白、煤黑、钴蓝、砖红批注。
- **组件系统：** 纸页边缘、直角和极轻投影；标签像索引；上传是材料入口；Modal 像独立页面；思维导图节点为薄纸条并带轻微角度。
- **动效：** 材料从工作区边缘滑入；批注在对应行出现；比较页并排；归档后纸页收入索引，不模拟翻页音效。
- **响应式：** iPad 保留双页比较；iPhone 改为材料栈，顶部保持当前材料索引。
- **参考：** Notion、Dovetail、Pitch Editor。拒绝拟物便签墙。

### 4.16 动态列阵 / Dynamic Columns

- **设计理念：** 宽屏用连续工作列同时表达任务、结果和详情，选中对象时列宽重组而不是打开新页面。
- **用户感受：** 连续、高效、现代。避免 Trello 看板复制。
- **Dashboard：** 任务列 24%、候选人列 38%、Agent 列 22%、岗位列 16%；选中候选人后中间列扩展。
- **排版与色彩：** Avenir Next / 苹方；紫蓝操作、白色表面、橙色提醒；列标题保持 14 px。
- **组件系统：** 6 px 圆角、垂直 Tabs、窄卡和共享详情；Drawer 变为详情列；思维导图节点使用左侧列色边并沿横轴展开。
- **动效：** 列宽 320 ms 重组；对象跨列移动；列表收窄保留头像和状态；恢复列宽时保持滚动位置。
- **响应式：** iPad 两列 + 详情抽屉；iPhone 使用顶部对象切换和单列详情。
- **参考：** Pitch Dashboard 与多栏 CRM 的连续上下文。拒绝多列都做等宽卡片。

### 4.17 智能副驾 / Contextual Copilot

- **设计理念：** Agent 建议出现在当前业务决定旁边，用户始终知道建议来源、影响和是否采纳。
- **用户感受：** 有帮助、可信、可控。避免把 AI 变成悬浮聊天球。
- **Dashboard：** 左侧优先任务；右上当前上下文建议；下方候选人与 Agent 事件。建议不遮挡业务内容。
- **排版与色彩：** Avenir Next / 苹方；青绿主色、琥珀建议、低饱和画布；AI 标记面积很小。
- **组件系统：** 建议条、解释 Tooltip、采纳/拒绝成对控件；输入聚焦有柔和外圈；Agent 卡和业务卡材质不同；思维导图选中节点可显示“AI 建议”标记。
- **动效：** 建议从当前组件边缘生成；采纳后与字段合并；拒绝向来源方向收回；解释层只淡入，不使用打字机效果。
- **响应式：** iPad 建议进入右侧抽屉；iPhone 建议紧随受影响字段，确认操作固定底部。
- **参考：** Granola 的上下文能力、Intercom Copilot、[Sana Agents](https://support.sana.ai/en/articles/238009-agents-in-sana-agents)。拒绝聊天优先的 AI 产品模板。

### 4.18 自动化流水线 / Guided Automation

- **设计理念：** 用户不需要理解技术步骤，但必须知道任务走到哪里、等待什么、失败后如何恢复。
- **用户感受：** 清楚、稳定、可恢复。避免技术日志成为主要界面。
- **Dashboard：** 顶部完整任务流程；左下 Agent 事件；右侧人工确认；下方岗位推进和结果摘要。
- **排版与色彩：** Inter / 苹方；蓝色进行、橙色等待、深色结果；步骤编号使用等宽数字。
- **组件系统：** 4–6 px 圆角；步骤节点、人工确认门、重试块和结果包；按钮动词明确；思维导图连线加粗，节点像步骤块。
- **动效：** 任务令牌推进；人工确认点停靠；失败沿原路径退回；恢复从 checkpoint 继续，不重新播放历史步骤。
- **响应式：** iPad 流程折为两行；iPhone 改纵向步骤，当前步骤详情嵌入节点下方。
- **参考：** Asana Workflows、Airtable Automations、Linear Workflows。拒绝 BPMN 工具界面。

### 4.19 证据智能 / Evidence Intelligence

- **设计理念：** AI 结论必须和来源证据、字段差异及业务写入影响一起出现。
- **用户感受：** 可信、透明、严谨。避免展示模型内部技术参数。
- **Dashboard：** 左侧证据对照 50%；右上候选人；右下写入影响；下方 Agent 事件。
- **排版与色彩：** Noto Serif SC 结论、Source Sans 3 数据；深青、砖红差异、白色证据面；引用编号使用等宽字。
- **组件系统：** 4 px 圆角、左侧证据脊线；按钮带引用号；字段标出来源；Modal 比较前后值；思维导图分支分别标识来源类型。
- **动效：** 证据与结论联动高亮；差异逐项出现；门禁通过产生一次外圈；拒绝写入时字段回到原值。
- **响应式：** iPad 保留双栏对照；iPhone 结论后紧跟证据，来源编号可跳转。
- **参考：** Dovetail 的研究证据和 Stripe Identity 的审核清晰度。拒绝“置信度仪表盘”主导页面。

### 4.20 协作交接台 / Collaborative Handoff

- **设计理念：** 协作不是增加评论，而是让责任、上下文、审批和交付物一起移动。
- **用户感受：** 明确、连续、无遗漏。避免企业 IM 信息流。
- **Dashboard：** 顶部任务归属；左侧交接队列；右侧优先任务；下方候选人和 Agent；交接对象始终显示原负责人、目标负责人和截止时间。
- **排版与色彩：** Avenir Next / 苹方；蓝色责任、莓红冲突、白色内容；责任人标签不使用大头像堆叠。
- **组件系统：** 7 px 圆角、左侧责任边、交接卡和审批状态；冲突 Modal 对比两方修改；思维导图节点的边色表示责任归属。
- **动效：** 任务沿责任线交接；负责人锚点迁移；冲突时停在中间并展开对照；完成后合并进业务资产。
- **响应式：** iPad 交接详情变底部抽屉；iPhone 使用“来源 → 接收人 → 截止时间”纵向卡，操作固定底部。
- **参考：** Asana 的任务归属、Affinity 的上下文、Intercom Inbox 的交接。拒绝聊天消息替代业务状态。

## 5. 技术实现与能力选择

### 5.1 工程结构

- `boards.js` 只保存设计 token、风格元数据和业务样例。
- Dashboard 允许复用无障碍和基础数据函数，但五个家族分别使用独立信息架构，二十个 variant 进一步改变栅格、主次关系和业务焦点。
- 组件页复用完整行为逻辑，二十个 variant 分别改变组件几何、材质、层级、表格、表单、浮层、思维导图和动效。这样既能长期维护，又不会形成二十份失控的复制代码。
- 首页预览图由 Playwright 从每套真实 Dashboard 的 1440 × 900 首屏生成，不使用与实际页面不一致的手绘封面。

### 5.2 插件与 Skill 判断

| 能力 | 是否使用 | 适用边界 |
| --- | --- | --- |
| Browser / Playwright | **必须** | 验证真实页面、按钮交互、桌面/iPad/iPhone 响应式、横向溢出、截图和预览图一致性 |
| Imagegen | 可选，本轮不作为主体 | 只在某套设计明确需要人物照片、纹理或品牌图像时生成受控位图；不用于替代 UI 组件设计 |
| Sites | 不使用 | 当前项目是既有 Vite + GitHub Pages 工程，不应为了托管改写技术栈 |
| Visualize | 不使用 | 适合对话内可视化，不适合替代可提交、可测试的多页面 React 工程 |
| 外部组件模板 | 仅作参考 | 可研究状态、动效和无障碍处理，但不能直接拼装成同质化组件墙 |

## 6. 验收门禁

### 6.1 差异性

1. 隐藏颜色和名称后，从首屏灰度结构仍能识别五个家族，二十套中大多数能根据主工作模型区分。
2. 任意两套不能同时拥有完全相同的 Dashboard 主次结构、主要按钮形态、数据列表语言和全部四组动效。
3. 每套至少出现三种贯穿 Dashboard、组件、思维导图和反馈状态的专属视觉语法。
4. 科技感必须来自产品行为和信息组织，不使用纯技术装饰填充差异。

### 6.2 完整性与交互

1. 二十套组件页全部覆盖第 2 节组件，不得按风格删减。
2. 所有可见按钮可操作或有明确禁用态；下拉、日期、标签、上传、Tabs、排序、批量选择、分页、Modal、Drawer 和 Toast 可实际触发。
3. 思维导图可完成选择、展开收起、缩放、重排和候选人绑定反馈；名称变化不得导致布局无规则抖动。
4. 每套四组动效均可手动触发，完成后业务状态明确；减少动态效果时不影响信息理解。

### 6.3 响应式与视觉质量

1. 1440 × 900、834 × 1194、390 × 844 均无页面级横向溢出。
2. 思维导图和宽表格可以在自身容器内滚动，但不得撑宽页面。
3. 文本、图标、状态和操作不能重叠或截断；动态内容不能改变固定工具栏、表头和按钮尺寸。
4. 每轮实现后生成三种视口接触图，与本方案逐套对照；不满足布局、组件或动效定义时继续修复。

## 7. 发布方式

1. 自动生成二十套 Dashboard 与组件页面，共四十个页面。
2. 自动生成二十张 Dashboard 首屏预览图并更新首页。
3. 完成构建、125 项 E2E 与响应式检查、人工接触图 Review。
4. 通过后提交到独立公开仓库，由 GitHub Pages 发布；不修改或污染 Hunter 主项目代码。
